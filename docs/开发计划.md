# 选课助手（油猴脚本）实现方案

## Context（背景）

目标：对正方教务系统（ZFSoft）的选课页面 `http://60.8.3.210:8090/jwglxt/xsxk/zzxkyzb_cxZzxkYzbIndex.html` 做自动抢课。

接口分析结论（见 `D:\My_Project\选课\接口分析.md`）：系统通过「双重教学班 ID（明文 `jxb_id` + 加密 `do_jxb_id`）」「多阶段选课流水线」「全上下文校验」「选课轮次绑定 `xkkz_id`」等手段防直连脚本。因此**核心思路是在浏览器内做 DOM/脚本级自动化，复用页面已有的 session、referer、加密逻辑**——油猴脚本是天然契合点，它运行在选课页上下文内，继承 `JSESSIONID`、`route`、`origin`、`gnmkdm`，无需自己维护登录态，也无需自己实现加密。

用户已确认的需求：
- 运行形式：**油猴脚本（Tampermonkey）**
- 自动化程度：**全自动 + 冲突重选**（持续刷新 → 检测目标 → 自动提交 → 遇冲突自动退选重选，无人值守）
- 目标课程匹配：课程名关键词 / 课程号 `kch` / 教学班 `jxb_id`，三者至少其一（或关系）

## 交付物

单个文件：`D:\My_Project\选课\选课助手.user.js`

- 纯前端 JS，无外部依赖，直接粘贴进 Tampermonkey 即可运行。
- 元数据 `@match` 锁定选课页 URL，`@grant` 申请 `GM_setValue / GM_getValue / GM_notification / GM_registerMenuCommand`。

## 关键接口调用清单（来自接口分析）

| 用途 | URL | 关键入参 | 关键出参 |
|---|---|---|---|
| 可选课列表查询 | `zzxkyzb_cxZzxkYzbPartDisplay.html` | 学生上下文 + `kklxdm=10` `rwlx=2` `xkly=0` `kspage/jspage` | `tmpList[]`（含 `kcmc/kch/jxb_id/jxbmc/xf`） |
| 展开教学班详情 | `zzxkyzbjk_cxJxbWithKchZzxkYzb.html` | 上下文 + `kch_id` + `xkkz_id` + `kklxdm` | `do_jxb_id`（256位加密串，提交用） |
| 前置探针（可选） | `zzxkyzb_cxXkTitleMsg.html` | `jxb_ids(加密)` + 上下文 | `{"flag":"1"}` 才可继续 |
| 提交选课 | `zzxkyzbjk_xkBcZyZzxkYzb.html` | `jxb_ids=do_jxb_id` + `kch_id/kcmc/rwlx/sxbj` + 上下文 | `{"flag":"1"}` 或 `{"flag":"0","msg":"...冲突..."}` |
| 已选课查询 | `zzxkyzb_cxZzxkYzbChoosedDisplay.html` | 学生上下文 | 已选课程（含 `do_jxb_id`，供退选用） |
| 退选 | `zzxkyzb_tuikBcZzxkYzb.html` | `kch_id + jxb_ids(加密) + xkxnm + xkxqm + txbsfrl` | `"1"` |

**提交/退选都要求带加密 `do_jxb_id`，且每次详情请求返回的值可能不同（随机 IV）**——所以脚本必须：列表命中 → 实时请求详情拿 `do_jxb_id` → 立即提交，不能缓存复用。

## 学生上下文参数来源（关键难点）

提交和查询都需一串学生身份参数：`jg_id zyh_id zyfx_id bh_id njdm_id xz ccdm xbm mzm xslbdm xsbj bklx_id xqh_id njdm_id_list jg_id_list xkxnm xkxqm` 等。

脚本按优先级三级获取，前一级失败自动降级：

1. **AJAX 模板缓存（最准，主方案）**：hook `jQuery.ajax`，拦截页面自身发出的任意含 `bh_id`/`zyh_id` 的选课请求，缓存其完整 `data` 作为「上下文模板」。之后脚本自己用该模板拼参数发请求。
2. **页面全局变量/DOM 提取**：扫描 `window` 上的配置对象和隐藏 input，提取上述字段。
3. **手动粘贴兜底**：配置面板提供文本框，允许用户粘贴一次完整的 `PartDisplay` 载荷，脚本解析成模板。

## 核心模块设计

1. **配置面板（UI）**：浮动面板，含——
   - 目标课程输入（多行，每行一个：`kch` 数字 / `jxb_id` / 关键词）
   - 刷新间隔（默认 2.5s，可调）
   - 干跑/实跑开关（干跑=只监控+匹配+提示，不提交）
   - 开始 / 停止按钮
   - 日志滚动区（每次查询、命中、提交结果）
   - 配置用 `GM_setValue` 持久化

2. **参数采集器**：实现上文三级策略，产出「上下文模板」并缓存；采集成功前自动按钮禁用。

3. **查询引擎**：定时器用模板参数 `$.ajax` 发 `PartDisplay`，解析 `tmpList`。

4. **目标匹配器**：遍历 `tmpList`，按「kch 精确 / jxb_id 精确 / 关键词包含 kcmc 或 jxbmc」或关系命中。

5. **选课执行器**（命中后串行）：
   1. 发 `cxJxbWithKchZzxkYzb` 拿 `do_jxb_id`
   2. （可选）发 `cxXkTitleMsg` 探针
   3. 发 `xkBcZyZzxkYzb` 提交
   4. 解析结果：`flag=1` 成功；`flag=0` 记冲突并进入冲突处理

6. **冲突重选器**：提交返回冲突时，查 `ChoosedDisplay` 定位冲突源：
   - 若冲突源是**可退的选修课**（`kklxdm=10` 且 `sfxkbj` 允许退）：发 `tuikBcZzxkYzb` 退选 → 重试提交目标课。
   - 若是必修课/不可退：放弃该目标，日志告警 + 通知。
   - 冲突源定位失败：安全放弃，避免误退。

7. **通知**：成功/失败用 `GM_notification` + 面板内 toast；可选声音。

## 实现步骤（分阶段）

1. **脚手架**：元数据 + 面板 HTML/CSS + `GM_*` 配置读写 + 日志函数。
2. **观察模式（先做，保证可校准）**：hook `$.ajax`，把页面所有选课相关请求/响应打到日志面板，帮助确认 URL、参数、DOM 结构（不同学校正方版本有差异，运行时校准选择器和字段名）。
3. **参数采集器**：三级策略，采集成功后显示「上下文已就绪」。
4. **查询 + 匹配**：定时查询 `PartDisplay`，解析并高亮目标，日志输出命中。
5. **干跑验证**：先只监控+提示，确认匹配准确、无误报。
6. **自动选课**：接入详情→提交链路。
7. **冲突重选**：接入退选→重选。
8. **通知与收尾**：桌面通知、声音、停止后状态复位。

## 风险与不确定点

- **页面 DOM/函数名/字段名**在运行时才能确定（正方版本差异），因此「观察模式」是第 2 步，先跑通观察再写死逻辑。
- **冲突自动重选有误退风险**：严格限定只退「可退的选修课」，其余只告警不动作。
- **频率**：默认 2.5s，避免过高频率被教务侧限流/封禁。
- **干跑默认开启**：首次使用不真正提交，用户确认无误后手动切「实跑」，降低抢错课风险。

## 验证方法

用户在有选课权限的时段登录选课页、安装 Tampermonkey 并加载脚本后：
1. **观察模式**：确认面板能打印页面 AJAX 请求与响应，上下文采集成功。
2. **干跑**：配置一个目标（如课程号 `207786` 风光摄影），确认脚本能定时查到并在日志正确命中，但**不提交**。
3. **实跑**：切「实跑」，观察命中后是否走完「详情→提交」，成功时收到通知，已选课程里出现该课。
4. **冲突场景**：配置一个与已选课时间冲突的目标，观察是否自动退选可退选修课后重选，或对不可退冲突安全告警。
