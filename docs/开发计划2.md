# 选课抢课 · 独立工具（Node.js + Playwright）实现方案

## Context（背景）

已有一个油猴脚本 `选课助手.user.js`（在选课页内做 DOM 级自动化，复用页面 session）。用户希望进一步做一个**独立工具**：虚拟浏览器 + 纯接口请求，体验更"黑盒"——用户只要给课程名（模糊匹配）+ 自己手动登录一次，之后脚本自动完成抢课，且希望能放到服务器无人值守。

经确认的关键决策：
- **技术栈**：Node.js + Playwright（现有 `选课助手.user.js` 的匹配/冲突/退选逻辑是 JS，可直接移植，几乎不重写）。
- **部署**：本地优先，但结构上留出服务器迁移余地（会话持久化、通知可配 webhook）。
- **登录**：**用户手动登录**（登录偶尔有验证码，用户自己处理）。工具不做自动登录、不做验证码 OCR。

因此工具职责收敛为：**开浏览器 → 等人登录 → 抓会话 cookie + 学生上下文参数模板 → 用纯 HTTP 请求跑抢课循环（列表→详情→提交→冲突重选）→ 会话过期则提示重登**。

核心结论（来自 `接口分析.md`，对独立工具同样成立）：选课管道是纯请求、没有一步需要点击；难啃的是「带合法 session + 实时取的加密 `do_jxb_id` + 完整学生参数」。Playwright 的价值正是：① 提供真实浏览器让用户登录拿 session；② `page.on('request')` 在网络层直接抓页面真实参数；③ `storageState()` 持久化会话供无人值守复用。

## 关键接口（来自 `接口分析.md`，工具要逐一调用）

| 用途 | URL（相对 `/jwglxt/xsxk/`） | 关键入参 | 出参 |
|---|---|---|---|
| 可选课列表 | `zzxkyzb_cxZzxkYzbPartDisplay.html` | 学生上下文 + `kklxdm/rwlx/xkly/kspage/jspage` | `tmpList[]`（`kcmc/kch/jxb_id/jxbmc/xf/xkkz_id`） |
| 展开详情 | `zzxkyzbjk_cxJxbWithKchZzxkYzb.html` | 上下文 + `kch_id + xkkz_id + kklxdm` | `do_jxb_id`（加密串，每次可能不同） |
| 提交选课 | `zzxkyzbjk_xkBcZyZzxkYzb.html` | `jxb_ids=do_jxb_id` + `kch_id/kcmc/rwlx/sxbj` + 上下文 | `{flag:1}` / `{flag:0,msg:冲突}` |
| 已选课 | `zzxkyzb_cxZzxkYzbChoosedDisplay.html` | 学生上下文 | 已选课程（含 `do_jxb_id`） |
| 退选 | `zzxkyzb_tuikBcZzxkYzb.html` | `kch_id + jxb_ids(加密) + xkxnm + xkxqm + txbsfrl` | `"1"` |

**铁律**：`do_jxb_id` 实时取、立即用，绝不缓存复用；流水线顺序「列表命中 → 详情 → 提交」一步不能省。

## 模块设计

### 1. 登录与会话持久化（`grab.js` 的 login 阶段）
- 启动 **有头** Chromium（本地）；`browser.newContext()` 打开选课页。
- 若 `state.json` 存在 → 先 `context.storageState()` 载入，`context.request` 打一次轻量探针（`ChoosedDisplay`）验证会话是否仍有效；有效则跳过登录直接进循环；失效则进入下一步。
- 提示用户"请在浏览器里登录选课页"，脚本轮询检测**已登录信号**（出现 `JSESSIONID` cookie 且跳转到选课 index，或首次成功捕获到 `bh_id` 请求）。
- 登录成功后 `context.storageState({ path: 'state.json' })` 落盘（含 cookies + localStorage）。**下次运行直接复用，无需再登；过期才重登。**
- 服务器场景：本地登录一次生成 `state.json` → 拷到服务器 → 服务器无头（`headless:true`）载入该文件直接跑；过期通知用户回本地重登再传。

### 2. 参数模板采集（`lib/params.js` + capture 阶段）
- 复用油猴「模板学习」思路，但更干净：`page.on('request')` 在网络层拦截页面自身发出的 `PartDisplay` / `ChoosedDisplay` / `xkBcZy` 请求，缓存其 `postData`。
- 页面加载通常会**自动**发一批初始化请求（已选课/列表），多数情况无需用户再点；若没自动发，程序化触发一次页面查询（`page.evaluate` 调页面查询函数，或点一次查询按钮）逼出 `PartDisplay`。
- 产出三类模板：`ctx`（学生身份：`jg_id/zyh_id/zyfx_id/bh_id/njdm_id/xz/ccdm/xbm/...`）、`query`（查询参数）、`submit`（真实提交参数，可选——没有则用 `buildSubmitParams` 兜底字段）。存进 `state.json` 复用。

### 3. 抢课循环（`lib/` 各模块 + `grab.js` 的 loop 阶段）
用 `context.request.post()`（**与浏览器 context 共享 cookie**，自动带 `JSESSIONID/route`），每条请求显式补 `referer`/`origin`/`x-requested-with: XMLHttpRequest`，URL 带 `gnmkdm=N253512`。

- **查询**：`params.buildQueryParams()`（从 query/ctx 模板 + `kklxdm` 覆盖 + `kspage=1&jspage=50`）→ POST `PartDisplay` → 解析 `tmpList`。
- **模糊匹配**：移植 `match.js` 的 `parseTargets`/`matchTarget` —— kch 精确 / jxb_id(32位hex) 精确 / 关键词包含 `kcmc` 或 `jxbmc`，或关系。
- **选课**（命中后串行，带 claim/cooldown 防并发与防狂刷，逻辑同 user.js）：
  1. POST `JxbWithKch` 拿 `do_jxb_id`
  2. `params.buildSubmitParams()` 拼提交参数 → POST `xkBcZyZzxkYzb`
  3. `flag=1` 成功通知并标记完成；`flag=0` 含"冲突"进冲突处理，否则冷却重试。
- **冲突重选**（移植 `conflict.js`，沿用"只退可退选修课"的保守策略）：
  - 查 `ChoosedDisplay` → `schedule.js` 解析上课时间找重叠课 → `isDroppable`（`kklxdm==='10' && rwlx==='2'`）判定 → 可退则 POST `tuikBcZzxkYzb` 退选后重试提交；不可退/定位失败则**安全放弃**只告警。

### 4. 参数序列化（`lib/params.js`）
正方接口数组用 `key[0]=x` 格式（不是 `key[]=x`）。Playwright 的 `form` 不直接产出这种 key，需一个 `flatten(obj)` 把嵌套/数组拍平成 `{'njdm_id_list[0]': ..., 'jg_id_list[0]': ...}`，再以 `x-www-form-urlencoded` 提交。此格式已由 `选课助手.user.js` 的 `U.qsParse`/`U.normArrays` 印证。

### 5. 通知与日志（`lib/notify.js`）
- 本地：控制台彩色时间戳日志 + `grab.log` 落盘；成功/失败可 `beep`。
- 服务器：`config.json` 里 `notify.webhook`（ServerChan/PushPlus 等 URL）可配，成功/会话过期时 POST 推送。

### 6. 干跑/实跑（沿用 user.js 的安全理念）
- `config.json` 的 `dryRun` 默认 `true`：只查询+匹配+日志，**不提交**。用户确认命中无误报后改 `false` 实跑。
- 首次使用流程：登录 → 观察模板就绪 → 干跑验证匹配 → 切实跑。

## 从 `选课助手.user.js` 直接移植的函数（不重写）

| 来源函数 | 目标文件 | 用途 |
|---|---|---|
| `parseTargets` / `matchTarget` | `lib/match.js` | 目标解析与模糊匹配 |
| `DAY_MAP` / `parseWeeks` / `parseSchedule` / `schedulesOverlap` | `lib/schedule.js` | 上课时间/周次解析与冲突判定 |
| `isDroppable` / `resolveConflict` / `dropCourse` / `fetchChoosed` | `lib/conflict.js` | 冲突重选（退可退选修课） |
| `buildQueryParams` / `buildSubmitParams` / `U.normArrays` | `lib/params.js` | 查询与提交参数拼装 + 序列化 |
| `markCooldown` / `canAttempt` / claim 状态机 | `grab.js` | 冷却/防并发/防狂刷 |

移植时只把 `$.ajax`/`GM_*`/DOM 操作替换成 `context.request`/文件读写/控制台，纯逻辑（匹配、时间解析、冲突判定）原样搬。

## 验证方法

1. `cd grabber && npm install`（下载 playwright 浏览器），`node grab.js` 启动。
2. **登录**：弹出浏览器 → 手动登录选课页 → 观察日志"会话已建立，模板已就绪"。
3. **干跑**：`config.json` 填一个目标（如课程号 `207786`），`dryRun=true`，确认循环能定时查到、日志正确命中、**不提交**。
4. **实跑**：`dryRun=false`，观察命中后走完「详情→提交」，成功时日志+通知，已选课里出现该课。
5. **冲突**：配一个与已选课时间冲突的目标，确认对可退选修课自动退选重选、对不可退冲突安全告警。
6. **会话过期**：手动登出或等过期，确认脚本探测到后提示重登（而非空转）。
7. **服务器迁移**：把 `state.json` + `config.json` 拷到服务器，`headless=true` 跑通（webhook 收到通知）。

## 风险与注意

- **登录偶发验证码**：用户已确认手动登录，工具绝不自动登录，规避 OCR/风控。
- **无头检测**：登录用有头浏览器（真实环境）；抢课循环走纯 HTTP（不依赖页面 UI），服务器上无头跑不影响。
- **字段名版本差异**：模板在运行时从页面真实请求捕获，自适应；若捕获不到，`state.json` 里留"手动粘贴一次 PartDisplay 载荷"兜底。
- **频率**：默认 2.5s，可配，勿过低防封禁。
- **冲突自动退选有误退风险**：严格只退 `kklxdm=10` 且 `rwlx=2` 的可退选修课，其余只告警。
- **凭据安全**：账号密码不入库（登录由用户手动）；`state.json` 含会话 cookie，勿外传。
